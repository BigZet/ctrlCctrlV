# Совместимость профиля и исправления после ревью

## Статус версий

Rust — основная развиваемая версия; Python остаётся пилотом с совместимым
профилем. Новые исправления в исходниках не означают, что опубликованные
бинарники уже содержат их. Полный паритет интерфейсов не заявлен.

## Один владелец профиля

Обновлённые версии берут `.profile.lock` до чтения и изменения данных и держат
открытый дескриптор до выхода. Rust использует `fs4::FileExt`, Python — `flock`
на macOS и эксклюзивный `LockFileEx` на первом байте Windows. Диапазоны блокировок
пересекаются. Файл не удаляется даже после выхода: удаление заблокированного
inode допускает двух владельцев. При аварии блокировка снимается ОС.

Повторный запуск обновлённой версии отправляет `activate.request`, но не открывает
модель и не пишет настройки. Ошибка доступа не считается занятым профилем.
Разные каталоги профилей не блокируют друг друга.

Перед обновлением закройте все старые копии. Старый Python знает только Qt
`app.lock`, старый Rust не знает новой блокировки вообще. Их одновременная работа
с новой версией не поддерживается. Новый Rust отказывается запускаться при
наличии старого `app.lock`. Если он остался после аварии, штатно запустите и
закройте Python-версию; не удаляйте блокировку работающего процесса.

## JSON и восстановление

Обе версии сохраняют неизвестные поля `settings.json` и `ui-state.json`, не
используя их как элементы интерфейса. В частности, Python не стирает Rust-поля
`setup_done` и `review_models`.

Невалидные настройки по-прежнему не попадают в виджеты. Но неявное сохранение
дефолтов поверх повреждённого файла запрещено. Для восстановления откройте
настройки, задайте значения и подтвердите сохранение. Точные исходные байты
сначала сохраняются в отдельный `settings-recovery-*.json`. Если резервная запись
не удалась, исходник не заменяется. Это локальный файл; он может содержать
приватные пользовательские поля и не включается в диагностику.

## История

Удаление одной транзакцией удаляет `entries` и связанные `runs`, включая
`raw_text`. Снимок для Undo хранится только в оперативной памяти 30 секунд.
Закрытие приложения или следующее удаление прекращает предыдущую возможность
Undo. Старая кнопка Undo не может восстановить более позднее удаление.

При временной ошибке БД снимок сохраняется для повторения в пределах срока.
Восстановление создаёт новый ID, если старый уже занят, и возвращает связанные
ответы и закрепление. На запуске убираются оставшиеся от старых версий ответы,
которым не соответствует запись с теми же `id + created`.

Удаление истории не очищает чужой буфер обмена, уже открытый редактор, резервные
копии ОС или блоки SSD. Гарантия относится к сохранённым строкам приложения;
криптографическое уничтожение всех копий не заявляется. Схема существующих
таблиц и пути профиля не меняются.

## Печать, форматы и время

Позиция продолжения учитывает уже отправленный символ отдельно от незавершённого
удаления автозакрытия. Такое удаление возобновляется только в исходном окне.
При перемещении курсора внутри того же окна приложение не может подтвердить
контекст: остановите операцию и исправьте текст вручную. Компенсация остаётся
опциональной эвристикой под конкретный редактор, а не универсальным протоколом.

Режимы Авто/Текст/CSV Rust влияют на инструкции модели и консервативное
преобразование целой таблицы. Неподдержанная разметка и некорректный результат
не отбрасываются. Для CSV показывается предупреждение, если прямоугольность
не подтверждена. Сырые ответы сохраняются отдельно. Редактор таблиц и XLSX
Python не перенесены в Rust в этой доработке.

В карточках ответов время относится к запросу модели. Статус «Скопировано»
измеряет время от готового изображения перед PNG-кодированием до завершения
записи буфера, включая последующее ожидание/подготовку модели. Четыре секунды —
цель скорости, не таймаут. Idle-выгрузка резервирует общую фазу обслуживания,
поэтому не прерывает активный OCR/стрим и не пересекается с новым запросом.

## Процессы и зависимости

Windows-движки обеих версий связываются с kill-on-close Job Object. Ошибка
привязки прекращает запуск и завершает собственный процесс, а не игнорируется.
Между созданием процесса и привязкой остаётся короткое окно; абсолютная гарантия
при аварии именно в этот момент не заявляется. На macOS обработка сигналов
также не гарантирует уборку после `SIGKILL`.

Минимальный Rust повышен намеренно с 1.88 до **1.89**: исправленная связка
rusqlite/libsqlite3-sys требует более нового компилятора. Обновлены уязвимые
SQLite и зависимости доверия сертификатам; требования к ОС не изменены.
RustSec предупреждения об устаревших транзитивных библиотеках остаются видимыми,
без подавления через ignore. Предупреждение `glib::VariantStrIter` относится
к Linux-зависимости, которой нет в графах Windows x64/macOS ARM64.

`cargo audit`/`pip-audit` не проверяют загружаемый llama-server, модель, системные
библиотеки и всю стандартную библиотеку Python. Их успешный результат не является
гарантией отсутствия любых уязвимостей.

## Приёмка

Регрессии используют синтетические временные профили, fake-движок, заглушки IPC
и собственные тестовые процессы. Автотесты не заменяют нативную проверку macOS,
настоящего VDI и конкретных редакторов. Платные запросы и публикация выпуска
не входят в автоматический прогон.
