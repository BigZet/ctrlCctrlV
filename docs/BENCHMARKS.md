# Замеры OCR на macOS и Windows

## OpenRouter на Windows: ограниченная интеграционная проверка

11 октября 2026, `qwen/qwen3-vl-8b-instruct`, один синтетический Python-снимок с кириллицей `python-light-20`, 1000 × 252 px, эталон 131 символ. Выполнены два платных запроса: первичный OCR и отдельная проверка текста. Использованы производственные инструкции, JSON-парсер, HTTP-транспорт и `Operation`; диагностический адаптер добавляет сортировку провайдеров по цене и потолок $0,50 / миллион входных, $1 / миллион выходных токенов. Ответ ограничен 512 токенами; повторов и перехода на другую модель нет. Каталог на момент проверки показывал $0,25 / $0,75 за миллион токенов. Стоимость по `usage.cost`: $0,000125235 и $0,000149490, всего **$0,000274725**.

Первичный OCR от готового изображения, включая PNG, полный ответ и запись в **системный Windows clipboard**, занял **4,562 с**. Цель 4 с превышена; полный ответ принят и скопирован. Получено 130 символов: отличие от эталона только в отсутствии завершающего перевода строки. Отдельная проверка заняла 4,765 с и оставила предложение без изменений. Исходник сохранён, автоматической публикации предложения нет, выбор пустого набора исправлений сохраняет исходник.

Предварительная отмена не отправляет запрос и сохраняет буфер. Настоящий запрос с заведомо неверной авторизацией получает HTTP 401 и также сохраняет буфер; пользовательский ключ в нём не используется. Исходные MIME-форматы системного буфера восстановлены после проверки; восстановление пропускается, если Windows сообщает, что пользователь сменил буфер.

Дополнительный отдельный запрос проверяет отмену **после отправки тела HTTPS POST**. Диагностический транспорт использует [событие httpcore `send_request_body.complete`](https://www.encode.io/httpcore/extensions/), игнорирует данные события и через 150 мс запрашивает отмену. Производственный `OCRProvider` завершает ожидание с `Cancelled` через **0,046 с**, закрывает транспорт и не принимает полный ответ; все форматы системного буфера и его Windows sequence number сохранены. На момент отмены заголовки ответа ещё не получены. Это подтверждает прекращение клиентского ожидания после передачи тела, но не остановку вычислений удалённого провайдера.

[Отчёт отмены](checks/windows-openrouter-cancel.json) содержит шесть успешных проверок. Три наблюдения совокупного счётчика расходов ключа в течение четырёх секунд не показали увеличения. Окончательная стоимость отменённой генерации неизвестна: её ID / usage не получены, сервер может учесть расход позднее. Воспроизведение на Windows: `python -m scripts.verify_openrouter_cancel`; скрипт отправляет один потенциально оплачиваемый запрос и не пишет в буфер.

Дополнительно выполнен оконный сценарий через исходный `Controller`: кнопка «Выделить область» запускает настоящий захват дисплеев, mouse-события Qt выбирают собственное синтетическое изображение, а затем фоновый OCR публикует результат в системном буфере и видимом предпросмотре. Перед запросом пиксели выбранного изображения сравниваются с эталоном: при отличии загрузка в облако не начинается. Изображение в предпросмотре сохранено полностью, публикация происходит в GUI-потоке. Ручная правка не меняет буфер до кнопки «Копировать текст». Исходные MIME-форматы буфера восстановлены, worker освобождён. На этом прогоне задержка **11,922 с**, стоимость одного запроса **$0,000125235**; текст вновь отличается только конечным переводом строки. Оба наблюдаемых OCR-запуска (4,562 и 11,922 с) превышают цель 4 с; быстрый результат не выбирается взамен медленного.

[Отчёт GUI](checks/windows-openrouter-gui.json) содержит десять успешных проверок. Воспроизведение: `python -m scripts.verify_openrouter_gui`. Используется отдельный каталог настроек, 100% монитор и source GUI; регистрация глобальных клавиш отключена, чтобы не менять работающий экземпляр пользователя. Выбор выполняется событиями Qt, а не физическим Win32-вводом мыши. Frozen EXE, настоящий VDI и macOS этим проходом не принимаются.

После этого проверен **сам Windows EXE из опубликованного ZIP**. С новым каталогом настроек и отдельными сочетаниями клавиш нативный hotkey запускает захват, Win32 SendInput выбирает собственный тестовый снимок, настоящий OpenRouter возвращает текст в системный буфер и видимый предпросмотр. Перед отпусканием мыши внутренние пиксели выделения сравниваются с эталоном; до захвата проверяется всё собственное окно. Получено 130 / 131 символов, отличие только конечным переводом строки. Верхняя оценка задержки **9,437 с**: таймер начинается перед нативным отпусканием кнопки и заканчивается обнаружением публикации / предпросмотра, поэтому дополнительно включает ввод и интервал опроса. Цель 4 с также превышена.

[Отчёт EXE](checks/windows-frozen-openrouter.json) содержит SHA256 бинарника, совпадающего с ZIP `ctrlCctrlV-windows-x64-ae85f64a.zip`; SHA256 ZIP повторно сверен с сохранённым отчётом сборки. Проверка использует обычный entrypoint EXE, без замены его провайдера или методов контроллера. Выбрана та же недорогая модель, 512 output tokens; повторов / других моделей нет. Конкретная стоимость этой генерации неизвестна: EXE не экспортирует usage / ID, наблюдаемое изменение общего счётчика ключа 0 не объявляется отсутствием оплаты. Исходные MIME-форматы буфера восстановлены; отдельный тестовый процесс завершён принудительно, работающая Desktop-копия сохранена. Штатный выход этим прогоном не проверяется. Воспроизведение: `python -m scripts.verify_frozen_openrouter`.

Это проверка работоспособности одного сценария, а не приёмка облачного качества / скорости на всех областях или нового модельного сравнения. Согласованные реальные снимки, медленная сеть, несколько размеров и нативная macOS остаются отдельной приёмкой. [Числовой отчёт OCR / reviewer](checks/windows-openrouter.json) не содержит ключа, текста или изображения. Воспроизведение на Windows с ключом в Credential Manager: `python -m scripts.verify_openrouter`. Скрипт выполняет платные запросы и временно использует системный буфер.

## Windows / RTX 3080: перенос выбранной модели

Проверка возможности ускорить текущий облачный маршрут: публичный [каталог endpoint выбранной Qwen3-VL 8B](https://openrouter.ai/api/v1/models/qwen/qwen3-vl-8b-instruct/endpoints) на 11 октября 2026 перечисляет один вариант — Parasail BF16, $0,25 / $0,75 за миллион токенов. `latency_last_30m` и `throughput_last_30m` отсутствуют (`null`); это не нулевые задержки. [Снимок метаданных](checks/openrouter-route-availability.json). Каталог не даёт альтернативного провайдера для обоснованного переключения по скорости; новые оплачиваемые запросы для этой проверки не выполнялись. Параметр сортировки сам по себе не является доказательством достижения 4 секунд.

11 октября 2026: Windows x64, RTX 3080 / 10 ГиБ VRAM, около 64 ГиБ RAM, драйвер 591.86, llama.cpp b11552 / CUDA 12.4. LightOnOCR-3 0.8B Q8_0 с прежними закреплёнными весами и bf16 vision-проектором. Команда `llama-server --list-devices` подтверждает CUDA0. Подготовка и прогрев — 2,781 с; самостоятельное `.exe` также успешно прогревает модель через `--smoke-model` и завершает дочерний процесс при выходе.

32 синтетические области с прежними текстовыми шаблонами, светлой/тёмной темой и расширенными фрагментами Python / SQL / JSON. На Windows используется Consolas вместо Menlo; изображения перегенерированы, поэтому этот прогон не является сравнением платформ на побитово одинаковых картинках. ## Методика

20 синтетических изображений: пять коротких шаблонов (Python, SQL, JSON, shell и русский/английский текст), каждый в светлой и тёмной теме и с размером шрифта 14 и 20. Шрифт Menlo, ширина изображения 1000 пикселей. Это пять разных содержаний в четырёх вариантах оформления, а не 20 независимых документов.

Таймер начинается с готового изображения и включает PNG-кодирование, полный запрос/ответ OCR и запись текста в настоящий системный буфер macOS через Qt. Ручное выделение, установка, загрузка и прогрев модели в него не входят. Исходные MIME-форматы буфера восстановлены после замера. Генератор и скрипт проверки находятся в `scripts/generate_fixtures.py` и `scripts/benchmark.py`.

## Что подтверждено и что ещё проверить

Этот замер подтверждает скорость коротких синтетических областей на указанном Mac с прогретой моделью. Он не подтверждает лимит на длинном коде, фотографиях, рукописи, реальном VDI, другом Mac или OpenRouter. Клавиатурный перенос в Cisco ещё требует отдельной ручной приёмки с разрешениями macOS и доступом к VDI.

Дополнительно проверена готовая `.app` через настоящий захват экрана: выделен видимый фрагмент из четырёх строк Python с русским комментарием в приложении «Просмотр». LightOnOCR-3 0.8B распознала его, автоматически записала в буфер и открыла предпросмотр; время в приложении — 1,03 с. Этот отдельный запуск не входит в таблицу 20 замеров. После проверки исходный буфер восстановлен.

LightOnOCR-3 0.8B остаётся экспериментальным кандидатом. Перед выбором постоянной модели нужно сравнить Qwen и другие OCR-модели на более широком наборе, включая реальные снимки пользователя. Проверка и исправление ошибок отдельным агентом — следующий этап, за пределами первоначального лимита 4 секунды.

Приложение отменяет просроченные операции и не публикует запоздалый ответ. Если сама системная запись буфера пересечёт границу 4 секунд, операция будет отмечена как просроченная, но уже выполненную запись нельзя атомарно отменить. Лимит не подменяется обрезанием ответа: незавершённая генерация считается ошибкой.

## Отдельная проверка текста Qwen3-VL 4B

## Исправленные и новые расхождения проверки

Повторены 20 коротких эталонов с отдельной проверкой Qwen 4B и 8B. Скрипт `scripts/accuracy.py` строит детерминированное выравнивание Левенштейна: ошибка — несовпадающий / отсутствующий символ эталона либо лишний символ между позициями эталона. Замена ошибочного символа другим ошибочным символом не считается исправлением. Исправления и новые ошибки считаются раздельно, по ранее ошибочным и ранее совпадавшим позициям. На повторяющемся тексте выравнивание может быть неоднозначным; это позиционная метрика, а не экспертная оценка каждого исправления.

У 4B улучшение общей дистанции скрывало четыре новых расхождения; поэтому предыдущая формулировка «число ошибок не увеличилось ни на одном снимке» не означает отсутствие внесённых ошибок. ## Подготовка различий для предпросмотра

На синтетическом тексте из 4000 одинаковых строк и одной исправленной строки полный `SequenceMatcher(autojunk=False)` занимал 1,161 с. После удаления совпадающих начала и конца подготовка изменений **вместе с diff** занимает 0,0019 с; 100 повторных чтений кэша — около 0,000012 с. Эти числа относятся к вычислению данных, без создания и отрисовки Qt-виджетов. [Замер](benchmarks/review-presentation-m4pro.json).

В приложении подготовка выполняется в рабочем потоке до передачи предложения в UI. Изменения и полный diff кэшируются; переключение галочек использует исходные подготовленные участки. Тест удерживает подготовку в рабочем потоке, редактирует текст в UI и проверяет отмену / отбрасывание устаревшего предложения. Отдельный тест проверяет, что matcher получает только изменённую середину и повторное чтение не пересчитывает её. Это устраняет выявленную задержку на повторяющихся границах, но не доказывает постоянное время для любых структур текста.

## Эксперимент с компактными исправлениями Vision + Qwen

`scripts/benchmark_patches.py` отправляет изображение и пронумерованные строки Vision в прогретую Qwen3-VL 4B. Модель возвращает только заменяемые диапазоны строк с точным `before` и предложенным `after`. Парсер проверяет номера, исходные строки, границы, порядок и отсутствие пересечений; отклоняет пустое предложение для непустого текста. Неизменённые строки и переводы строк сохраняются. Добавление после последней строки без завершающего перевода строки также покрыто тестом.

Общий бюджет запроса — 4 секунды. Из 20 коротких областей завершились 6, из них 2 совпали с эталоном без финального перевода строки. На шести завершённых областях исходно было 5 ошибочных позиций: исправлена 1, добавлены 4 новых, после проверки осталось 8 расхождений. Средние и длинные (по 6) не завершились до дедлайна. Скорость подходит для дальнейшей проверки, но буквальная точность пока недостаточна: например, обе модели распознают латинское `name` как кириллическое `пате` внутри смешанной строки.
