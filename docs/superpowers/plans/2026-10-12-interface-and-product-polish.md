## Global Constraints

- «Сохранить PySide6, светлую и тёмную темы, поддержку Windows и macOS».
- «Лёгкая модель распознаёт и копирует результат; тяжёлая вызывается только вручную в предпросмотре».
- «Сравнение “Было / Стало” открывается отдельным окном»; правила `ReviewResult.select()` сохраняются.
- «Компактные панели, короткие подписи, одна основная кнопка на экран»; без постоянных инструкций, повторяющихся статусов и технических подробностей.
- «Сохранить все текущие пользовательские и незакоммиченные изменения. Новые настройки получают совместимые значения по умолчанию».
- Интерфейсы `OCRProvider.recognize(...) -> str`, экспорта и существующих сигналов остаются совместимыми. Дополнительный API не должен ломать прежних потребителей.
- Схему `history.sqlite3` и способ хранения API-ключей не менять. Состояние оформления хранится отдельно в `ui-state.json`.
- Активную правку ячейки фиксировать перед сменой представления, сохранением, копированием и проверкой несохранённого результата.
- Сохранить атомарную запись, ручное расширение файла, имя с датой/временем и последний **успешный** каталог. Отмена/ошибка записи не меняют каталог.
- CSV/XLSX сохраняют буквальные значения: ведущие нули, запятые, переносы, кавычки, строки вида `=SUM(...)`. Первая строка остаётся редактируемыми данными и включается в экспорт.
- Новый захват, история, повтор, закрытие и перезапуск проходят существующую защиту правок «Сохранить / Не сохранять / Отмена». Отмена системного диалога сохранения не разрешает потерю результата.
- Отменённые и запоздалые OCR/review/download callbacks не меняют новый результат, буфер или новую очередь.
- Текст, снимки и ключи не попадают в диагностику/логи. Исходный ответ модели и отмена удаления существуют только в памяти текущего сеанса.
- Платные вызовы не нужны для реализации, тестов и визуальной приёмки. Реальный облачный benchmark — отдельный ограниченный запуск недорогой vision-модели в пределах доступного бюджета; никаких автоматических платных повторов.
- Нативную macOS, Cisco VDI и отдельную чистую Windows-машину не объявлять проверенными по контрактным тестам на текущем Windows-компьютере.
- Уточнение пользователя во время исполнения: «mac и vdi пока не тестим а примеров нет сам нагенерь». Нативные Mac/VDI исключены из текущего прохода по его решению; корпус OCR для этого прохода генерируется синтетически и так обозначается в результатах. Кроссплатформенная совместимость кода сохраняется.

## Review Focus

Пять особенно важных проверок распределены по соответствующим задачам:

1. Переключение вида при активной ячейке, неверном CSV и последовательности Undo/Redo не теряет правки — задачи 02 и 05.
2. Unicode, emoji, CRLF, табуляция и пустые строки не смещают поиск, подсветку и выбранное исправление — задачи 04 и 06.
3. Удалённый максимальный ID истории может быть занят новой записью; восстановление и закрепление не должны затронуть чужую запись — задача 10.
4. Масштаб 200% на экране 1920×1080 оставляет меньше места, чем старый минимум окна; действия должны оставаться достижимыми без уменьшения шрифта — задачи 01 и 13.
5. Повтор области после смены DPI/монитора, новый захват после отмены и поздний ответ старой модели не должны использовать устаревшее состояние — задачи 07, 12 и 14.

## 1. Принятые решения и границы работ

### Что изменится для пользователя

- В результате появится компактный переключатель «Текст / Таблица». Автоопределение выполняется при открытии; ручной выбор действует до следующего результата и не запускает OCR.
- Поиск открывается по Ctrl+F / Cmd+F; исправления получают переходы вперёд/назад; таблица — структурные команды через контекстное меню.
- Историю можно закреплять и восстанавливать после удаления в течение **30 секунд**. Изображения в историю не добавляются.
- «Повторить область» явно снимает прежний прямоугольник заново. Область хранится только до завершения приложения; новый сеанс начинает без неё.
- «Исходный ответ OCR» доступен через меню результата, только для текущего распознавания. Это текст распознавания до очистки LightOn и преобразования таблицы, без HTTP/JSON-конверта, служебных полей и ключей.
- Внешний вид приводится к единой сетке; существенные действия остаются на виду, редкие операции уходят в понятные меню. CSV и XLSX остаются отдельными кнопками.

### Общая геометрия

Все размеры ниже — **логические пиксели Qt**, не физические пиксели снимка.

| Элемент | Решение |
|---|---|
| Интервалы | 8 px внутри группы, 16 px между группами, 24 px для крупных внешних полей; компактные диалоги — 16 px |
| Основные поля/кнопки | Целевая высота 36–38 px с учётом `sizeHint()` и метрик системного шрифта |
| Действия таблицы | 32–34 px; строка библиотеки 48–52 px для обычного названия |
| Строка выбора модели | 38–44 px для одной строки; длинные названия допускают увеличение высоты |
| Короткие значения | Естественная ограниченная ширина; модель, путь и редактор получают оставшееся место |
| Рамки | Один визуальный контейнер на область, отчётливый разделитель панелей, минимум вложенных обводок |
| Акцент | Одна основная кнопка на текущей поверхности; выключенные действия нейтральны, ошибка отличается от фокуса |
| Узкие окна | Перестановка групп и прокрутка содержимого; основные действия закреплены в доступной части окна |
| Маленький экран / 200% | Размер ограничивается `availableGeometry()`; если обычный минимум не помещается, включается компактная компоновка, а не окно за пределами экрана |

Общие роли и размеры сосредоточить в `theme.py`. Чисто косметическим значениям не нужны тесты, дублирующие stylesheet; проверять реальную геометрию и поведение.

### Работа с текущей копией

Базой является **текущая рабочая копия**, включая незакоммиченные и новые файлы. Не начинать с чистого HEAD: он не содержит всей принятой реализации. Исходное состояние уже сохранено в `artifacts/ui-polish/baseline/`, результаты — в `artifacts/ui-polish/progress.md`; не заменять эту базу более поздним снимком. Не применять `reset`, `clean`, массовое форматирование или автоматический коммит чужих изменений. Каждый этап получает отдельный проверяемый diff и запись результата в этом плане.
