# Символы вне раскладки VDI

В Rust-приложении: **Настройки → Печать → Клавиши раскладки (VDI, RDP)**.
Переключение раскладки «Сочетанием внутри сессии» остаётся прежним: сочетания должны непосредственно выбирать английскую и русскую раскладки, а не циклически переключать языки.

Раньше символы, отсутствующие в установленных раскладках, незаметно отправлялись через `KEYEVENTF_UNICODE`. VDI может превращать эти события в `?` или другие неверные символы. Теперь в режиме клавиш раскладки такого отката нет.

## Точный текст (Alt+Unicode Hex)

Режим по умолчанию для символов вне раскладки. Обычный текст передаётся клавишами раскладки, остальные печатные символы BMP — физической последовательностью **левый Alt → плюс цифрового блока → четыре hex-цифры → отпустить Alt**. Перед последовательностью выбирается английская раскладка в сессии; следующее русское слово снова переключает её на русскую. Буфер удалённой сессии не используется.

**Необходима настройка внутри удалённой Windows**, не локального компьютера:

1. С разрешения администратора VDI задайте строковый (`REG_SZ`) параметр `EnableHexNumpad` со значением `1` в `HKEY_CURRENT_USER\Control Panel\Input Method`. Например, в командной строке сессии:

   ```bat
   reg add "HKCU\Control Panel\Input Method" /v EnableHexNumpad /t REG_SZ /d 1 /f
   ```

2. Сохраните работу, выйдите из сеанса Windows и войдите снова. Простое отключение/повторное подключение VDI может сохранить старый сеанс и не применить настройку.
3. Включите Num Lock в сессии. В целевом редакторе проверьте вручную `Alt` + **плюс цифрового блока** + `2014`, отпустите Alt. Должно появиться `—`. Аналогично: `00D7` → `×`, `2013` → `–`.
4. Только после успешной проверки запускайте печать полного текста.

Программа сама не меняет реестр, не определяет наличие удалённой настройки и не может подтвердить доставку символов. Нужны поддержка клиента VDI и целевого редактора; режим не гарантирует результат без проверки внутри конкретной сессии. Если политика запрещает настройку, используйте второй режим. Emoji вне BMP (`U+FFFF`) и неизвестные управляющие символы отклоняются до начала ввода. Обычный способ «Символы Unicode» не изменён и по-прежнему поддерживает emoji в совместимых локальных приложениях.

## Совместимые замены (меняют текст)

Не требует Alt+Unicode Hex. Перед печатью выполняются явные замены:

- `—`, `–`, `−`, `‑`, `‐` → `-`;
- `×` → `x`, `÷` → `/`;
- `«»`, `“”`, `„` → обычные двойные кавычки; `‘’`, `‚` → апостроф;
- `…` → `...`, `№` → `No`, `•` → `*`;
- неразрывные/узкие пробелы `U+00A0`, `U+202F`, `U+2007`, `U+2009` → обычный пробел.

Это **не буквальная передача исходника**; замены могут изменить смысл кода. Буфер и исходный текст не переписываются. Позиции прогресса и продолжения учитывают фактически печатаемые символы, в том числе три точки вместо многоточия. Символ без клавиши и без предусмотренной замены вызывает ошибку с его `U+`-кодом до первого нажатия. Автозакрытие кавычек/скобок и автоотступы редактора настраиваются отдельно.

## Проверка исправления

Для первичной проверки обоих режимов используйте пустой документ с отключёнными автозакрытием и автоотступами и строку `Здесь — 6×V100; с. 289–294.`. Точный режим должен сохранить строку буквально; совместимый — напечатать `Здесь - 6xV100; с. 289-294.`.

Синтетический многострочный эталон: `crates/platform/tests/fixtures/vdi-report.txt`. Пользовательские документы в публичный тестовый корпус не включаются. Автоматические тесты проверяют маршрутизацию символов, отсутствие Unicode-пакетов в режиме раскладки, физические scan-коды Alt+Hex, остановку до ввода неподдерживаемого текста и продолжение внутри развёрнутого многоточия. Они не заменяют проверку реального VDI.
