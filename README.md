# ctrlCctrlV: Python-приложение и исходная версия Hammerspoon

Разработка Python-версии ведётся в [BigZet/ctrlCctrlV](https://github.com/BigZet/ctrlCctrlV). Исходный Swift/Lua-проект: [alexeyk222/ctrlCctrlV](https://github.com/alexeyk222/ctrlCctrlV); история его коммитов сохранена.

## Python-приложение для macOS ARM64 и Windows x64 — пилот 0.1.1

**[Скачать установщики Windows и macOS](https://github.com/BigZet/ctrlCctrlV/releases/latest)** · [Описание выпуска 0.1.1](docs/releases/v0.1.1.md).

Предварительная версия на Rust (Tauri 2): [выпуск 0.2.0](https://github.com/BigZet/ctrlCctrlV/releases/tag/v0.2.0) · [описание](docs/releases/v0.2.0.md) · [исходники](crates/app/README.md).

Новая версия использует PySide6 и работает как приложение в меню macOS или системном трее Windows. Общее ядро, интерфейс и OCR-провайдеры используются на обеих платформах. Подробности: [план](PLAN.md), [роадмап](ROADMAP.md), [замеры](docs/BENCHMARKS.md), [актуальный статус](docs/STATUS.md).

Реализовано:

- выделение области экрана, OCR, автоматическое копирование и предпросмотр;
- локальные модели через управляемый `llama-server`: Metal на Apple Silicon, CUDA 12.4 на Windows / NVIDIA;
- LightOnOCR-3 0.8B/4B Q8 (экспериментальные community GGUF), Qwen3-VL 4B/8B Q4;
- OpenRouter: изменяемая vision-модель и API-ключ в macOS Keychain / Windows Credential Manager;
- два протокола: JSON для универсальных VLM и транскрипция с пустым prompt для специализированных OCR-моделей;
- установка, возобновление загрузки и повторы при обрыве сети, SHA256-проверка, прогрев, выгрузка и удаление локальных моделей через интерфейс;
- ручное уточнение OCR: отдельное окно «Было / Стало», посимвольные различия и выбор исправлений;
- редактируемые таблицы, копирование и вставка TSV, экспорт CSV / XLSX; сохранение текста с определением расширения;
- история с поиском, закреплением, открытием в редакторе и отменой удаления в течение 30 секунд; избранные модели и фильтры, компактный прогресс загрузки;
- переключение результата «Текст / Таблица», поиск внутри результата, команды строк/столбцов с Undo, просмотр исходного ответа OCR;
- повторный свежий снимок прежней области; при смене монитора или DPI требуется новое выделение;
- необязательная проверка синтаксиса Python / JSON в предпросмотре, без исполнения кода;
- печать текста, настраиваемые задержки, обработка Tab и компенсация автоотступа через Shift+Home;
- настраиваемые глобальные сочетания; на Windows выявляются конфликты регистрации и печать останавливается также при смене окна внутри одного приложения.

### Windows: запуск готовой сборки

Скачайте `ctrlCctrlV-0.1.1-windows-x64-setup.exe` из [GitHub Releases](https://github.com/BigZet/ctrlCctrlV/releases/latest) и запустите мастер. Установка выполняется для текущего пользователя без прав администратора, ярлык появится в меню «Пуск». Удаление через «Параметры → Приложения» сохраняет настройки, историю и модели. Перед обновлением полностью завершите программу через трей.

Также доступен ZIP без установки: распакуйте его и откройте `ctrlCctrlV/ctrlCctrlV.exe`. Сохраняйте весь каталог приложения вместе с `_internal`. Python, CUDA Toolkit и Ollama отдельно не нужны; для CUDA нужен установленный драйвер NVIDIA. Основная целевая конфигурация — Windows 11 x64 / RTX 3080. Приложение работает в текущем пользовательском сеансе; защищённые рабочие столы и ввод в приложения с более высокими правами недоступны.

Первый запуск открывает мастер выбора локального OCR или OpenRouter. Локально можно явно выбрать GPU или CPU; загрузка начинается только по кнопке «Скачать модель». Позже модели доступны в разделе «Модели», подготовка — на экране «Работа». Движок, необходимые библиотеки и выбранная модель скачиваются с проверкой SHA256. Можно отменить загрузку и продолжить её позже. Перед подготовкой проверяются оборудование и доступная память; при ошибке GPU приложение предлагает CPU или OpenRouter, а выбранный режим сохраняется. CPU использует отдельный пакет без CUDA и может работать медленнее. После установки локальный OCR работает офлайн. Настройки и модели находятся в `%LOCALAPPDATA%/ctrlCctrlV`; API-ключ хранится отдельно в системном хранилище.

Горячие клавиши по умолчанию на Windows:

| Сочетание | Действие |
|---|---|
| `Ctrl+Alt+4` | Выделить область → OCR → буфер |
| `Ctrl+Alt+V` | Напечатать текст буфера в активном окне |
| `Ctrl+Alt+Esc` | Отменить операцию |

Сочетания изменяются в разделе «Система». `win` и `cmd` обозначают клавишу Windows; сочетания с ней могут быть заняты ОС. При конфликте приложение показывает проблемное сочетание. Печать передаёт Unicode через SendInput; поддержку конкретного клиента Cisco и редактора нужно проверить отдельно. При работе с редактором отключите автоматическое закрытие кавычек/скобок; профиль Shift+Home проверяйте на небольшом фрагменте.

Из исходников, в PowerShell (Python 3.11+ x64):

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -e ".[dev]"
.venv\Scripts\python.exe -m ctrlcctrlv
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe scripts/build_windows.py
```

Сборщик проверяет упакованное приложение через `--smoke` и создаёт ZIP только после успешной проверки. С установленным Inno Setup 6.3+ команда `python scripts/build_windows.py --installer` дополнительно создаёт Setup.exe и SHA256. На чистом CI-агенте флаг `--verify-installer` проверяет установку, повторную установку, запуск и удаление; при существующей установке эта проверка отказывается работать. Для диагностики доступен `--console`. Синтетическую проверку реального Win32-ввода в отдельном тестовом окне запускает `.venv\Scripts\python.exe -m scripts.verify_windows`; чужие окна и системный буфер она не использует. Для проверки прогрева установленной модели: `ctrlCctrlV.exe --smoke-model lightonocr-3-0.8b --acceleration gpu` (либо `cpu`). Диагностический запуск требует отдельного неиспользуемого каталога данных: работающий экземпляр не считается успешной проверкой. Сборка не подписана сертификатом Windows; SmartScreen может показать предупреждение. Cisco/OpenRouter остаются отдельной приёмкой.

### macOS: установка и запуск

Скачайте `ctrlCctrlV-0.1.1-macos-arm64.dmg` из [GitHub Releases](https://github.com/BigZet/ctrlCctrlV/releases/latest), откройте образ и перетащите приложение на значок Applications. Извлеките образ и запустите ctrlCctrlV из «Программ». Нужны macOS 14+ и Apple Silicon (M1 и новее); Python отдельно не нужен. Это пилотная сборка с ad-hoc подписью, без нотарификации Apple. Если Gatekeeper блокирует доверенную загрузку, после попытки запуска используйте «Конфиденциальность и безопасность → Всё равно открыть». При обновлении сначала полностью закройте прежнюю копию; системные разрешения выдавайте установленной копии, которую будете использовать.

Новые сборки разработки находятся в `artifacts/builds/dist/ctrlCctrlV.app`. Они не заменяют установленную копию: пока нет постоянного сертификата подписи, обновление может сбросить её разрешения. Описанные новые возможности относятся к исходникам и тестовой сборке; установленная копия может отставать.

В настройках:

1. В разделе «Система» проверить разрешения. Рядом с каждым недостающим разрешением есть кнопка «Разрешить»: она вызывает системный запрос для этого разрешения и открывает соответствующий раздел настроек macOS. Когда доступ предоставлен, кнопка скрывается. Статусы обновляются автоматически, горячие клавиши подключаются после выдачи доступа. Для печати нужен Accessibility, для захвата — Screen Recording, для глобальных клавиш — Input Monitoring. После изменения разрешений может понадобиться перезапуск приложения.
2. В разделе «Модели» загрузить нужную модель, затем на экране «Работа» нажать «Подготовить». Дождаться готовности. Модель прогревается до начала OCR.
3. Для облачного режима выбрать OpenRouter, ввести ключ и нажать «Сохранить». Доступность модели в OpenRouter проверяется при запросе. LightOnOCR-3 не предполагается доступной там автоматически.
4. Включить «Показывать результат»: с флажком текст копируется и открывается для проверки, без флажка — сразу копируется без окна результата. Выбор сохраняется автоматически.
5. Нажать «Распознать область» или использовать горячую клавишу. Выделение выполняется внутри одного выбранного монитора; область через границу двух мониторов пока не поддерживается.

В предпросмотре кнопка «Уточнить» запускает отдельную сверку со снимком. В «Настройки → Распознавание» провайдер и модель проверки выбираются независимо от провайдера OCR; доступен контекст проверки. Локальная Qwen должна быть установлена через список моделей. Если эта же модель уже подготовлена, она используется повторно; иначе запускается отдельный процесс и выгружается по окончании проверки. Запрос проверки имеет отдельный бюджет 30 секунд после подготовки модели и измеряется отдельно от первичного OCR.

Предложение не изменяет текст и буфер автоматически. В отдельном окне «Было / Стало» снимите галочки с ненужных исправлений, сравните посимвольные различия и нажмите «Применить и скопировать» либо «Отклонить». Редактирование текста отменяет текущую проверку и аннулирует старое предложение. Принятие доступно для отмены в редакторе; «Вернуть исходный текст» в меню редактора возвращает первоначальное распознавание без автоматического копирования. Результат проверки может содержать ошибки: [измерения на эталонах](docs/BENCHMARKS.md).

В редакторе доступны подсветка и форматирование Python, SQL, Java и JSON. «Форматировать» выполняет правки по кнопке; результат можно отменить, а буфер обновляется только при копировании. «Копировать» закрывает предпросмотр. Для Python и JSON также доступны подсказки синтаксиса. При ошибке разбора строка отмечается в поле номеров; нажатие показывает подробности. Неполный фрагмент может быть корректным в своём файле; успешный разбор также не доказывает точность OCR. Проверка работает в фоне после копирования, код не исполняется и не исправляется. Tab вставляет табуляцию, Ctrl+Tab переводит фокус к другим элементам окна.

При ошибке OCR в окне настроек появляется «Повторить OCR»: используется неудавшийся снимок и текущие сохранённые настройки. Кнопка доступна после завершения предыдущего запроса.

Предпросмотр начинается с режима «Вписать». Доступны масштаб 25–400%, 100% и скрытие снимка; ширина панелей и видимость снимка запоминаются. Исходный снимок сохраняется для уточнения. Ctrl+S / Cmd+S открывает сохранение текста с определением расширения, а для таблицы — выбор CSV / XLSX. Последний успешно использованный каталог запоминается.

При ошибках откройте «Настройки → Система → Диагностика». Отчёт сначала показывает краткое состояние; подробности можно раскрыть, скопировать или сохранить в JSON. Он содержит версии, тип подписи и хеш сборки, разрешения, наличие локальных моделей, состояние движка, свободное место, RAM и RSS процесса (если доступны). Тип подписи и хеш позволяют отличить сборки при разборе проблем с разрешениями macOS. Снимки, распознанный текст, буфер, ключи, пользовательские пути, имя владельца сертификата и имя компьютера не собираются; ключевое хранилище не читается. Отчёт никуда не отправляется. Если файлы модели есть, а движок удалён, в настройках появится «Восстановить движок».

Для печати можно использовать глобальное сочетание или кнопку «Напечатать буфер» на экране «Работа»: приложение сохраняет текущий текст буфера, скрывает окно и даёт время выбрать редактор. Отмена во время задержки прекращает запуск; смена приложения перед началом или во время печати останавливает ввод.

Кнопка «Остановить» появляется во время операции. В трее «Остановить» отключена вне операции. Другие действия временно отключаются; подготовка изображения и OCR выполняются в фоне. Названия моделей сокращены, полные параметры доступны в подсказке.

Сочетания по умолчанию:

| Сочетание | Действие |
| --- | --- |
| `Ctrl + Option + Cmd + 4` | Выделение → OCR → буфер и предпросмотр |
| `Ctrl + Option + Cmd + V` | Печать текста в активном приложении |
| `Ctrl + Option + Cmd + Esc` | Остановка текущей операции |

Настройки, движок и модели хранятся в `~/Library/Application Support/ctrlCctrlV`. API-ключ хранится отдельно в Keychain, не в JSON-настройках. Чтобы заменить ключ, ввести новый и сохранить. Перезапуск движка не требует изменения системной конфигурации или установки Ollama.

### Цель скорости 4 секунды и ограничения пилота

Время считается от готового изображения выделенной области, включая PNG-кодирование, запрос и запись полного текста в системный буфер. 4 секунды — целевой показатель скорости, а не таймаут. Если распознавание длится дольше, оно продолжается; интерфейс показывает прошедшее время и позволяет отменить операцию. Полный результат копируется и после превышения цели; рабочий индикатор показывает только полосу и прошедшее время. Отменённые и неполные ответы не копируются. «Остановить» прерывает и сетевое ожидание; после закрытия соединения можно начать новый OCR. Отдельная защита соединения: 10 с на подключение, 120 с ожидания сетевых данных; она не задаёт общий срок OCR.

Первый локальный замер LightOnOCR-3 0.8B на Apple M4 Pro / 48 ГБ: 20 коротких синтетических скриншотов, все менее 4 секунд. Сохранение текста пока не идеально — подробные результаты и границы проверки указаны в `docs/BENCHMARKS.md`. Исторические расширенные замеры четырёх моделей использовали прежний жёсткий таймаут 4 с на длинных областях; текущая версия продолжает запросы после этой границы. Кроссплатформенный кандидат RapidOCR / PP-OCRv5 CPU завершил 64 экспериментальных запроса до 4 секунд без записи буфера, но требует улучшения точности и ещё не включён в приложение. Реальные VDI-снимки остаются отдельной проверкой.

LightOnOCR транскрибирует в Markdown; программа сохраняет этот результат буквально, не удаляет разметку и не исправляет код автоматически. Проверяйте отступы и символы в предпросмотре. Сверка со снимком доступна через «Проверить текст» в предпросмотре.

Cisco VDI пока недоступен для интеграционной проверки. Эмуляция Unicode может зависеть от клиента. Автоотступы и автозакрытие скобок различаются между редакторами; компенсация по умолчанию выключена, автоматическое закрытие скобок/кавычек следует отключить в целевом редакторе. Смена вкладки или курсора внутри одного приложения не обнаруживается как смена фокуса.

### Открыть окно работающего приложения

Приложение отображается в Dock. После закрытия окна процесс продолжает работать; активация приложения возвращает окно настроек, когда нет активного захвата или печати. Повторный запуск установленной копии также открывает окно уже запущенного экземпляра. Меню в верхней строке macOS остаётся дополнительным способом управления. Для полного завершения выберите «Выход» в этом меню.

### Тумблер включён, а доступ не определяется

Статусы показывают результат системных API macOS, а не состояние тумблера в настройках. Если тумблер включён, но после перезапуска приложение не получает доступ, запись может относиться к предыдущей сборке. У пилота ad-hoc подпись: её designated requirement привязан к конкретному хешу сборки и меняется при обновлении ([Apple TN3127](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)).

Для восстановления разрешения вручную удалите старую запись ctrlCctrlV в нужном разделе приватности, добавьте фактически установленную копию (обычно `/Applications/ctrlCctrlV.app`; `~/Applications/ctrlCctrlV.app`, если вы установили её туда), включите доступ и перезапустите приложение. Используйте только эту установленную копию для проверки. Приложение не сбрасывает разрешения самостоятельно. Для сохранения доступа между сборками нужна постоянная подпись сертификатом разработчика; один постоянный путь этого не гарантирует.

### Запуск из исходников

Нужны Python 3.11+ и macOS 14+ на Apple Silicon. Инструкции Windows находятся выше.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m ctrlcctrlv
```

Проверки и сборка:

```bash
.venv/bin/python -m pytest -q
QT_QPA_PLATFORM=offscreen .venv/bin/python -m ctrlcctrlv --smoke --data-dir /tmp/ctrlcctrlv-smoke
.venv/bin/python scripts/build_macos.py --development
```

Тестовая сборка сохраняется отдельно в `artifacts/builds/dist/ctrlCctrlV.app`; она не заменяет установленную копию. Флаги `--development --dmg --verify-dmg` дополнительно создают DMG/SHA256 и проверяют запуск копии, извлечённой во временную папку. Для обновления с постоянным сертификатом: `.venv/bin/python scripts/build_macos.py --identity "имя сертификата" --install`. Сначала полностью закройте установленное приложение. Если сертификат отсутствует, сборка не переключается молча на ad-hoc подпись.

Обычный `--smoke` также проверяет HTTP-транспорт, принятие результата после цели 4 с и отмену ожидания на локальном сервере `127.0.0.1` с синтетическими данными. Внешние сервисы и системный буфер не используются.

Для диагностики загрузки уже установленной модели через фоновые задачи GUI: `dist/ctrlCctrlV.app/Contents/MacOS/ctrlCctrlV --smoke-model lightonocr-3-0.8b`. Эта проверка открывает интерфейс, прогревает модель и завершает приложение с выгрузкой движка; экран не захватывает и клавиши не отправляет.

Воспроизводимые скриншоты и локальный бенчмарк (модель предварительно установить через интерфейс):

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python scripts/generate_fixtures.py
.venv/bin/python scripts/benchmark.py --model lightonocr-3-0.8b
```

Бенчмарк использует синтетические изображения, на время меняет системный буфер и восстанавливает исходные форматы после завершения. Результаты записываются в `artifacts/benchmark.json`; каталог `artifacts` исключён из Git. Выходной текст эталонов не публикуется в диагностические логи пользовательского приложения.

# Исходная версия Hammerspoon: CTRL+C / CTRL+V в VDI на macOS

При работе через VDI общий буфер обмена между локальным Mac и удалённым рабочим столом может быть отключён.

Этот проект добавляет два сценария:

```text
VDI → Mac
выделить область экрана → OCR → локальный clipboard

Mac → VDI
локальный clipboard → эмуляция клавиатурного ввода → VDI
```

Основные горячие клавиши:

| Комбинация                | Действие                                                                  |
| ------------------------- | ------------------------------------------------------------------------- |
| `Ctrl + Option + Cmd + 4` | Выделить область → OCR → сохранить текст в clipboard Mac                  |
| `Ctrl + Option + Cmd + V` | Напечатать содержимое clipboard в активном окне через эмуляцию клавиатуры |
| `Ctrl + Option + Cmd + R` | Перезагрузить конфигурацию Hammerspoon                                    |

---

# 1. Что используется

Для работы нужны:

* **Hammerspoon** — горячие клавиши, screenshot, clipboard и эмуляция клавиатуры;
* **Apple Command Line Tools / Swift** — сборка OCR;
* встроенный в macOS **Vision Framework**;
* `VNRecognizeTextRequest` — системный OCR Apple.

# 6. Проверка Swift

Перед сборкой OCR рекомендуется проверить, что Swift и macOS SDK совместимы.

```bash
cat >/tmp/test.swift <<'EOF'
import Foundation
print("Foundation OK")
EOF

xcrun swiftc /tmp/test.swift -o /tmp/test && /tmp/test
```

Ожидаемый результат:

```text
Foundation OK
```

Если появляется ошибка:

```text
this SDK is not supported by the compiler
Please select a toolchain which matches the SDK
```

значит версии Swift compiler и macOS SDK несовместимы.

На тестовом Mac с:

```text
macOS 15.1
```

проблема возникала с:

```text
Command Line Tools 16.2
```

и была устранена установкой:

```text
Command Line Tools for Xcode 16.1
```

Скачать нужную версию можно на Apple Developer Downloads:

```text
https://developer.apple.com/download/all/?q=Command%20Line%20Tools%2016.1
```

После установки повторите тест `Foundation OK`.

# 8. Сборка OCR

Создать отдельный Swift module cache:

```bash

```

Собрать OCR:

```bash
xcrun swiftc \
  -module-cache-path ~/.cache/swift-ocr \
  -framework Vision \
  ~/.hammerspoon/scripts/ocr.swift \
  -o ~/.hammerspoon/scripts/ocr
```

Проверить, что файл появился:

```bash
ls -lh ~/.hammerspoon/scripts/ocr
```

Проверить запуск:

```bash
~/.hammerspoon/scripts/ocr
```

Ожидаемый результат:

```text
Usage: ocr <image>
```

# 13. Ограничения

OCR хорошо подходит для переноса текста и большинства фрагментов кода, однако распознавание исходного кода не гарантирует 100% точность.

Особенно внимательно стоит проверять:

```text
,
.
:
;
()
[]
{}
_
|
```

Мелкая пунктуация и отдельные строки вроде:

```text
)
```

иногда могут быть пропущены OCR.

Перед выполнением перенесённого кода рекомендуется быстро проверить результат.

## Рабочее пространство и история

Четыре раздела: Работа, Модели, Конфигурация, История. В Моделях можно установить, подготовить, выгрузить, удалить комплект и добавить GGUF vision-модель по ссылке Hugging Face. OpenRouter предлагает обновляемый список VLM с ценами. OCR и проверка могут выполняться у разных провайдеров.

Авто преобразует выделенную целиком таблицу в CSV; Текст сохраняет представление, CSV включает проверку числа столбцов. Качество зависит от выбранной модели. История OCR, правок и печати хранится локально: доступны просмотр, поиск, копирование, повторная печать и удаление. Во время действий индикатор появляется в углу экрана без захвата фокуса.
